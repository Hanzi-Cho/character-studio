# Initial Character Render Generation

기능 ID: **F-001** · 한국어 이름: **초기 캐릭터 렌더 생성**  
기록일: 2026-10-24 · 구현 기준: v4 작업 트리 (`ac93896` 이후) · 플랫폼: PC 로컬 웹, React + TypeScript + Three.js  
상태: 초기 모델·회전·6표정 구현 및 v4 윤곽/얼굴 개선. 수치·시각·기능 검증은 아래 근거를 따른다. 사용자 최종 닮음 평가는 별도다.

## 1. 목적과 범위

비개발자가 앱을 열자마자 치이카와를 참고한 입체 캐릭터를 보고, 마우스로 회전하며, 표정과 허용된 속성을 바꾸게 한다. 초기 모델은 이후 채팅 편집의 출발점이다. 사용자가 요구한 **머리가 몸통보다 약간 넓은 비율**을 유지하면서 얼굴·귀·팔다리와 표정의 인상을 맞춘다.

이 기능에는 서로 다른 두 과정이 있다.

- **제작 과정:** 웹 표본 조사 → 분류 → 좌표 측정 → 설계값 채택 → 절차적 모델 구현 → 수치·시각 검증. 개발 단계에서 수행한다.
- **실행 과정:** 검증된 캐릭터 문서 읽기 → 고정된 rig와 geometry 생성 → 재질·비율·표정 반영 → 상호작용. 앱 실행 때 웹 이미지를 수집하거나 AI로 새 메시를 생성하지 않는다.

현재 포함: 단일 캐릭터, 정면·회전·확대, 키보드 조작, 6표정, 색·몸 비율·귀/눈 크기·장식 변경, 로컬 저장, PNG/JSON 내보내기 UI. 후속: 자유로운 부위 생성, 얼굴 윤곽의 자연어 편집, 외부 AI 대화, 실제 모바일 기기 검증. 관련 채팅 확장은 [F-002](character-chat-implementation-plan.md)에서 정의한다.

## 2. 재현 가능한 제작 절차

1. **스타일과 제약을 먼저 고정한다.** 원작 그림, 봉제 인형, 피규어, 얼굴만 있는 상품을 분리한다. 다른 상품의 수치를 하나의 정답처럼 평균내지 않는다. 현재는 원작의 얼굴 특징을 간결한 3D로 표현하며 머리/몸통 폭 약 1.08은 사용자 요구를 따른다.
2. **최소 50개 유효 시각 표본을 확보한다.** 출처 URL·캐릭터·표정·정면/사면/측면·상품군·중복 여부를 기록한다. 같은 이미지의 리사이즈는 새 표본으로 세지 않는다. 여러 그림이 든 한 시트는 선택한 프레임 ID를 별도 기록한다. `50장 파일`과 `50개 그림 표본`을 혼동하지 않는다.
3. **측정에 적합한 대표 표본을 선별한다.** 정면에 가깝고 귀/정수리/턱이 보이는 자료를 비율 측정에 사용한다. 모자·가림·강한 원근·자세 변화가 있으면 해당 수치는 제외한다. 크기 정규화 때 원본 종횡비를 보존한다.
4. **랜드마크와 오차를 기록한다.** 원본 크기, 측정 좌표계, 머리 좌우/정수리/턱, 몸통 폭, 눈·볼·입 중심, 귀 뿌리/끝, 팔·발 중심, 눈썹 끝점을 남긴다. 관찰값·채택값·판단 이유·미측정 항목을 분리한다.
5. **측정값을 rig로 번역한다.** 최대 폭/높이뿐 아니라 윤곽의 높이별 폭, 귀 접합부, 얼굴 곡률, 선 굵기를 다룬다. 코드에 값이 반영되었는지 실제 생성된 버텍스·월드 좌표로 확인한다. 상수만 맞아도 화면은 다를 수 있다.
6. **표정을 하나의 얼굴 설계로 만든다.** 눈썹 각도만 바꾸지 않고 눈 모양·반사광·입 곡선·눈물·볼 선을 함께 비교한다. 공통 몸체와 표정 전용 요소를 분리한다. 원본의 감정 이름과 서비스의 해석을 구분한다.
7. **동일 조건에서 렌더를 비교한다.** 기본 색·기본 크기·장식 없음, 동일 카메라/조명으로 정면·사면·표정별 화면을 저장한다. DOM의 선택 상태뿐 아니라 WebGL 화면이 실제로 바뀐 뒤 캡처한다. 사용자 저장본은 별도 검증 데이터와 분리한다.
8. **기능과 닮음을 각각 판정한다.** 스키마·회전·저장·표정 보존 테스트와 시각 대조를 따로 기록한다. 부족한 부분을 부위·수치·근거·다음 검증으로 남긴 뒤 다시 측정한다. 사용자의 최종 인상 평가를 자동 테스트로 대체하지 않는다.

v4에서는 높이별 윤곽 폭 9구간을 추가 측정하고 가변 선 굵기를 구현했다. 선 굵기는 원본의 전 픽셀 통계가 아닌 확대 관찰에 따른 설계값이다. [윤곽 원시값](../reference-data/contour-v4.json)과 [재현 스크립트](../evidence/chiikawa-fidelity-v4/measure-reference.py)를 보존한다.

## 3. 실제 조사 근거와 한계

- [스티커 검토](../CHIIKAWA-REFERENCE-REVIEW.md): 공개 미리보기 3시트의 120프레임을 검토하고 치이카와 그림 **57개**를 선별했다. A 17개 + B 22개 + C 18개이며, 57개의 독립 이미지 파일을 내려받았다는 뜻은 아니다.
- [추가 사진 실측](../CHIIKAWA-MEASUREMENTS.md): 38개 이미지 파일 중 중복 6개·다른 캐릭터 1개를 제외한 **31개** 고유 치이카와 사진. [인벤토리 CSV](../reference-data/reference-inventory.csv)에 포함/제외를 남겼다.
- [랜드마크 JSON](../reference-data/landmarks.json): 대표 12개 이미지의 수동 좌표. 모든 57개 그림과 31개 사진에서 모든 치수를 측정한 것은 아니다. `학습`은 시각적 관찰·분석이며 모델 학습/fine-tuning을 수행하지 않았다.
- 정면 머리 높이/폭의 독립 대표 5개는 0.7493, 0.7386, 0.7543, 0.7159, 0.7832. 중앙값 **0.7493**, 범위 **0.7159~0.7832**. 머리 전체가 가려진 샘플과 턱 경계가 불명확한 통통 인형은 이 집계에서 제외했다.
- 기존 대표 사진은 정사각형 원본이어서 600×600 측정 좌표를 사용했다. 수동 클릭 오차는 대략 ±5px, 모호한 경계 ±12px, 각도 ±5~10°로 추정했다. 통계적으로 검증된 신뢰구간이 아니다.
- 일반 봉제 인형의 머리/몸통 폭 약 1.42~1.58을 그대로 적용하지 않았다. **현재 약 1.08은 사용자 선호를 반영한 채택값**이며 치이카와 전체 상품의 공식 표준 비율이 아니다.

## 4. 수치 정본과 실제 메시

정본: [chiikawaRig.ts](../../src/adapters/chiikawaRig.ts), [ChiikawaModel.ts](../../src/adapters/ChiikawaModel.ts). 기본 크기 1, 장식 없음 기준. 단위는 모델 공간 단위이며 cm가 아니다. X=좌우, Y=위, +Z=얼굴 앞쪽.

`u=x/머리폭`, `v=(정수리Y−y)/머리높이`, 즉 `x=2.32u`, `y=3.10−1.76v`. **위치 v는 머리 높이로, 얼굴 요소의 가로·세로 크기는 모두 머리 폭 W로 정규화**한다.

| 항목 | v4 명목 설계값 | 해석 |
| --- | --- | --- |
| 머리 폭 × 높이 | 2.32 × 1.76 | H/W=.758621, W/H=1.318182 |
| 머리 위 / 아래 | Y=3.10 / 1.34 | 귀 제외 |
| 머리 깊이 비율 | .70 | LatheGeometry의 Z 축 비율 |
| 몸통 | 폭 2.15, 하단 .23, crown 1.79, 깊이 1.28, Z=−.08 | 타원체의 숨은 윗부분이 머리 안으로 겹침; 사용자 높이 이동 기준 top=1.34 |
| 머리/몸통 폭 | 1.079070 | 사용자 선호, 모든 공식 상품의 표준값이 아님 |
| 귀 pivot / lift | (±.69,2.95,−.03) / .125 | pivot 기준 로컬 Y 이동 |
| 귀 폭 × 높이 × 깊이 | .37 × .40 × .34 | 넓어진 뿌리, 바깥 18° |
| 귀 실제 메시 중심 | (±.728627,3.068882,−.03) | pivot/lift/회전 적용 |
| 팔 중심 / 치수 | (±1.08,1.07,.04) / .44 × .24 × .28 | 바깥 아래 35° |
| 발 중심 / 치수 | (±.44,.20,.13) / .27 × .36 × .32 | 수직에서 바깥 4° |

v3의 열린 아래 머리 윤곽은 몸과 이어져 긴 캡슐 인상을 만들었다. v4는 **닫힌 머리 + 안쪽에서 겹치는 몸통**을 한 geometry buffer로 합친다. 한 매끈한 manifold mesh로 융합한 것은 아니다. 정면/사면의 턱과 가려진 겹침으로 연결하며, 머리/몸통별 vertex 구간을 유지한다. 따라서 체형 수정이 얼굴을 늘리지 않는다. 몸체 outline은 접합부 검은 선을 피하기 위해 사용하지 않는다.

머리 `(정규화 반지름, v)` 제어점:

```text
(0,1), (.50,.95), (.69,.90), (.80,.85), (.925,.75),
(1,.60), (.99,.45), (.90,.30), (.85,.25), (.75,.17),
(.64,.08), (.40,.025), (.21,.004), (0,0)
```

[Kitan 기본 얼굴](https://kitan.jp/wp-content/uploads/2024/12/normal.jpg)의 실제 800×800 이미지에 기존 600 좌표의 머리 bbox (30,100)–(565,519)를 환산했다. grayscale<245의 3연속 픽셀 경계로 대략적인 단면 폭을 읽고 240/250에서도 민감도를 기록했다. 자동 의미 segmentation이나 공식 설계도 측정이 아니다. 귀가 섞이는 v=.10은 제외했다. 수동 bbox 오차는 여전히 ±5px 수준이다.

## 5. 얼굴과 6종 감정 설계

| --- | --- |
| 눈 중심·크기 | (±.16,.51), .125×.130 W; 양안 간격 .320 W |
| 위 반사광 | 눈 로컬 폭의 x=−.25~+.27, 높이의 y=−.34~+.035인 비정형 폐곡선 |
| 아래 반사광 | 눈 로컬 x=−.28~+.29, y=.14~.385의 초승달 폐곡선 |
| 볼 | (±.30,.61), .180×.125 W; radial .68~1 구간 smoothstep alpha 감쇠 |
| 볼 사선 | 3개, 가로 간격 .035 W; u±.010/.009, v±.025/.024; 반지름 .0055 W |
| W 입 | 중심 v≈.67, 폭 .14 W; 반지름 .011 W, 가운데 줄기 .0105 W |
| 기본 아래 입 | u=−.024~+.024, v=.735~.744, 반지름 .009 W |

| 선 가중치 | 반지름 × (.76+.24·sin(πt)); 양 끝 구형 cap, 피부 깊이 방향은 약 ±.001로 얇게 투영 |

정확한 폐곡선 control point는 `buildOpenEye`, `muzzle`, `buildFace`를 정본으로 한다. `faceGeometry.ts`는 CatmullRom 폐곡선→삼각분할→2단계 subdivision→표면 투영을 담당한다. 큰 삼각형이 곡면 안으로 잘리는 현상을 막는다. 눈 크기 변경 시 x/y만 pivot 기준으로 바꾼 후 z를 머리 곡면에 다시 맞춘다. 단순 group scale을 쓰지 않는다.

| 표정 | 눈썹 각도 / v | 눈·입·세부 | 근거 |
| --- | --- | --- | --- |
| 기본 | +10° / .300 | 열린 비정형 눈·위 하이라이트/아래 초승달, W, 아래 입 | Kitan normal, A-13 |
| 웃음 | +8° / .285 | 감은 눈 중심 .493/끝 .510~.508, W lift −.025, 열린 입 v=.653~.790/흰 내부 .674~.763, 아래 입 .825~.835 | Kitan nikkori, A-07 |
| 슬픔 | +22° / .300 | 4점 물결 눈썹, 눈물 v=.60~.709/검은 외곽, W와 찡그린 아래 입 | Kitan nakigao, A-10/C-21 |
| 화남 | −30° / .320 | 눈 상부 안쪽 긴장(상반부 v에 −side·x·.035), W와 아래 찡그림 | Kitan yaruki와 C-30의 해석 |
| 놀람 | 0° / .260 | 열린 눈 높이×1.10, O 입 (0,.70) .061×.084 W | B-22/C-11 |
| 졸림 | 0° / .330 | 감은 눈 중심 .529/끝 .500, 작은 입 (0,.70) .032×.043 W | C-09/C-29 |

각도는 바깥→안쪽으로 높아지면 +이다. 곡선 전체 기울기 하나가 아니라 **끝점 사이 각도**를 실제 메시에서 측정한다. Kitan yaruki의 공식 의미는 의욕이므로 화남과 동일한 원본 표정이라고 주장하지 않는다. [공식 Kitan 5종](https://kitan.jp/products/okaonosqueeze_chiikawa/), [스티커 ID 목록](../CHIIKAWA-REFERENCE-REVIEW.md)을 참조한다.

표정 patch는 몸·색·이름·장식·귀/눈 크기·카메라를 보존한다. 기본/슬픔/화남/놀람 눈 그룹은 사전 생성하고 웃음/졸림은 열린 눈을 숨긴다. 표정 전환만으로 body/eye buffer를 새로 생성하지 않는다.

## 6. 실행 구조와 자원 관리

```text
bootstrap → App(runtime: gateway, renderer factory, ChatPanel)
UI/MCP → HTTP → CharacterService → interpreter / repository
                             └→ committed event → SSE → useStudio
CharacterDocument → renderer port → ThreeCharacterRenderer(model port)
                                            └→ ChiikawaModel + rig + faceGeometry
```

- domain/application은 React·Three·HTTP 구현을 모른다. 화면과 모델의 실제 조립은 composition root가 담당한다. [전체 구조 리뷰](../reviews/architecture-and-replaceability-review.md).
- 머리 profile 96분할×회전64, torso sphere48×32, 귀/팔다리 shared sphere36×24. 볼6링×48, 선32×8+양 끝 cap, 얼굴 patch56 curve samples 및 삼각형 subdivision2단계.
- v4 CPU geometry pool은 73개(렌더러 floor 제외). 이는 6표정 전체 풀이고 GPU는 실제 보인 것부터 업로드된다. 새 표정 최초 방문의 GPU 수 증가와 누수를 구분한다.
- bodyHeight 변화 시 head 이동 `1.11×(bodyHeight−1)`, 머리 x/y 비율 유지. body 구간만 별도 변형. dispose 시 geometry/material/볼 texture를 해제한다.
- 변경·회전·damping이 있을 때만 RAF 예약, DPR≤2. 기본 camera(0,2.04,8.2), target(0,1.67,0), FOV32°, 거리4.2~11, damping.12, 모바일 폭 보정.
- roughness.87/metalness0, ACES exposure1.35, hemisphere2.4/key3.8/fill1.2. 동일 조명에서 전후를 비교한다.
- [Human Atlas 연구](../HUMAN-ATLAS-RESEARCH.md)의 장수명 scene·공유 자원·부분 갱신을 적용한다. 4,096 instance 실험은 상세 캐릭터 4,096개 성능 보장이 아니다.

## 7. 입력·저장·오류·권한

문서 v1의 bodyWidth .75~1.35, bodyHeight .8~1.3, earSize .6~1.8, eyeSize .65~1.4, 6표정과 none/bow/star만 허용한다. 서버 단일 writer가 `.data/character.json`·직전 `.bak`·최근50회 이력을 저장한다. 손상/잘못된 schema/오래된 revision은 거부한다. 초기 렌더와 QA가 사용자 저장본을 기본값으로 덮어쓰지 않는다.

undo/redo/reset은 명시적 service action이다. UI의 undo/redo 버튼은 자연어 해석기를 거치지 않는다. JSON import는 같은 gateway.patch를 사용하며 파일 읽기 전 revision을 잡는다. 채팅 실패 시 입력을 남기고 최신 상태를 다시 읽는다. HTTP/SSE snapshot도 런타임 검증한다.

로컬 단일 사용자이며 로그인/RBAC·기기간 동기화·AI 전송은 없다. 외부 AI/ChatKit은 [계획 문서](character-chat-implementation-plan.md), 12종/날개/저장 슬롯은 [확장 전략](character-catalog-and-customization-strategy.md)이며 구현 완료가 아니다.
