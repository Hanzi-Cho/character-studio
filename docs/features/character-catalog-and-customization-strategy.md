# Character Catalog and Customization Strategy

2026-10-24 · 상태: 향후 확장 전략. 이번 구현 범위는 치이카와 품질 개선과 구조 정비이며, 아래 12종·날개 생성 기능이 완성된 상태는 아니다.

## 목표 흐름

**기본 모델 선택 → 즉시 3D 표시 → 채팅으로 날개/장식/표정 추가 → 저장 → 다시 열기 → 초기화로 선택한 기본 모델 복원.**

`기능 저장`은 캐릭터의 수정 결과를 저장하고, 만든 부품·표정 설정을 재사용 가능한 preset으로 보관한다는 의미로 해석한다. 저장된 결과를 다시 열었을 때 재생성을 위해 AI를 다시 호출할 필요가 없어야 한다.

## 12종 카탈로그

[공식 캐릭터 분류](https://chiikawamarket.jp/products/4571609387930)를 바탕으로 한 후보는 치이카와, 하치와레, 우사기, 모몽가, 쿠리만쥬, 랏코, 시사, 헌책방/카니, 아노코, 데카츠요, 오데, 키메라다. 정확한 12종 구성과 한국어 표시명은 카탈로그 착수 때 확정한다.

같은 몸체의 색만 바꾸는 12종으로 만들지 않는다. 둥근 기본형, 긴 귀, 큰 꼬리/피막, 갈기·무늬, 큰 체형 등 **실제 형태의 차이**에 따라 modeling adapter를 나누고, 공통 얼굴 도형·부위 부착·렌더링 자원 관리만 재사용한다. 각 캐릭터에 참고 목록, 비율/랜드마크, 6표정, 정면·측면·뒷면, 품질 판정을 갖춘다.

출시 순서는 대표 3종(치이카와/하치와레/우사기)으로 공통 모델 계약을 검증한 뒤, 다른 형태군 3종, 나머지 6종이다. 처음부터 12개 구현을 복사해 분기문을 늘리지 않는다. 카탈로그에는 완료 모델만 선택 가능하게 표시한다.

## 데이터와 서비스 경계

```text
CharacterTemplate (읽기 전용·버전 고정)
  id / version / displayName / thumbnail / modelAdapterId
  defaultConfig / capabilities / attachmentSockets / referenceReview
                  ↓ instantiate
CharacterInstance (사용자 문서)
  schemaVersion / id / templateId / templateVersion / revision
  overrides / parts[] / expressions[] / activeExpression / name
                  ↓ validate + resolve
ResolvedCharacter → Modeling adapter → Scene renderer
```

템플릿은 Git으로 관리하는 기본값이고, 인스턴스는 사용자 저장 데이터다. 렌더러는 대화 문장을 알지 않으며, 채팅 서비스는 Three.js 객체를 알지 않는다. UI는 catalog/application port를 통해 읽고 수정한다. 모델 버전 업데이트로 사용자가 저장한 모습이 조용히 바뀌지 않도록 `templateVersion`을 고정한다. 업그레이드는 별도의 되돌릴 수 있는 변경으로 처리한다.

## 날개와 장식

모델마다 `head.top`, `head.left`, `head.right`, `back.upper`, `hand.left`, `hand.right` 같은 의미 있는 socket을 제공한다. socket은 모델의 로컬 위치·방향·허용 크기를 반환하며, 채팅이나 UI에 모델별 월드 좌표 계산을 맡기지 않는다.

첫 단계는 검증된 **날개/리본/모자/안경 레시피 라이브러리**다. 채팅은 레시피 ID와 제한된 크기·색·각도·대칭·부착 위치를 지정한다. 부품 instance ID로 추가/수정/삭제하고, 같은 요청의 재시도로 중복 부품이 생기지 않게 한다. 몸 비율이나 기본 모델이 바뀌어도 socket 기준으로 다시 배치한다. 미지원 부착점은 설명하고 임의의 위치에 붙이지 않는다.

후속의 임의 형상 생성은 별도 asset generation adapter다. 결과 geometry/GLB와 출처·버전·해시·제한을 실제 파일로 저장하고 재열기 때 재사용한다. AI가 JavaScript/shell을 만들어 런타임에서 실행하는 방식은 사용하지 않는다. 부품 수·polygon·texture·파일 크기 예산과 교차/가림 검증이 필요하다.

## 새로운 표정

기본 6종은 불변 preset으로 둔다. 사용자 표정은 별도 ID로 저장하고 눈/눈썹/입/볼/눈물의 제한된 곡선·변형 값으로 정의한다. 표정의 의미 이름과 실제 도형을 함께 저장한다. “수줍게 웃어줘”는 지원 요소를 조합한 제안으로 만들고 사용자가 결과를 확인할 수 있게 한다.

표정 변경은 몸/날개/장식을 보존한다. 작은 썸네일과 3D 얼굴이 서로 다른 하드코딩을 갖지 않도록 동일한 expression definition을 각 renderer가 해석한다. 현재 SVG 시안과 3D 얼굴은 별개 구현이므로 이 공통화는 동적 표정 도입 전에 필요하다.

## 초기화와 저장의 의미

- **초기화:** 현재 인스턴스가 참조하는 템플릿 버전의 초기 설정으로 돌아간다. overrides·추가 부품·사용자 표정 선택을 제거하고 기본 표정을 복원한다. 한 개의 undo 가능한 작업으로 실행한다.
- **초기화가 지우지 않는 것:** 별도로 저장한 캐릭터, 사용자 부품/표정 preset 라이브러리, 다른 인스턴스. 삭제는 별도 기능이다.
- **자동 저장:** 성공한 도메인 변경마다 원자적으로 저장하고 저장 중/완료/실패를 구분한다. 실패한 상태를 “저장됨”으로 표시하지 않는다.
- **이름 붙여 저장:** 현재 모습을 별도 slot으로 저장한다. 카탈로그 선택/다른 문서 열기가 기존 저장본을 덮어쓰지 않게 한다.
- **내보내기/가져오기:** manifest JSON + 필요한 asset 파일을 묶고 schema/version/hash를 검증한다. 누락 asset·알 수 없는 레시피·지원하지 않는 버전은 조용히 대체하지 않는다.
- **v1 이전 데이터:** 현재 캐릭터 문서를 치이카와 template + v1 속성 overrides로 변환한다. 원본 백업, 반복 실행 안전성, 실패 시 원문 보존, 실제 재열기/복원 테스트를 갖춘다.

## 구현 순서와 수용 기준

| 순서 | 범위 | 완료 근거 |
| --- | --- | --- |
| 1 | 이번 치이카와 품질 기준·UI/채팅/렌더러 교체 경계 | 화면·수치·기존 편집/저장 회귀 |
| 2 | Template registry + instance v2 + 기본 모델 선택 + 초기화 버튼 | 3종 선택 즉시 표시, 기본 버전 복원, undo, 다른 저장본 보존 |
| 3 | 부품/socket + 날개/장식 레시피 + 채팅 도구 | 요청→추가→회전→저장→재열기→삭제/undo가 한 흐름으로 통과 |
| 4 | 공통 expression definition + 사용자 표정 저장 | 썸네일과 3D 일치, 몸/부품 보존, export/import 일치 |
| 5 | 12종 품질 확보 + preset 라이브러리 | 12개 각각 원본 대조와 회귀, 아직 없는 모델을 완료로 표시하지 않음 |
| 6 | 실제 모바일·외부 AI 호스트 | 터치/키보드·복귀·지연·연결/해제·권한 거부 검증 |

PC 한 화면에서 현재 모델만 지연 로드하고 카탈로그는 가벼운 썸네일을 사용한다. 12개의 고품질 WebGL 장면을 모두 미리 생성하지 않는다. 캐시는 참조 수·예산에 따라 해제하고, 부품 하나의 변경으로 장면 전체를 다시 만들지 않는다.

향후 정량 목표는 대상 PC에서 기본 모델 선택→첫 표시 p95 500ms 이내(로컬 asset 준비 상태), 설정 적용→표시 p95 100ms 이내, 휴대폰에서 회전 30fps 이상으로 제안한다. 아직 측정하거나 보장한 수치가 아니다. 실제 기기·모델 복잡도 측정 후 예산을 확정한다.

## 미결정과 범위

12종 구성/표시명, 저장 slot·preset 라이브러리 UX, 임의 형상 생성의 허용 범위, AI 비용·계정, 모바일 저장/동기화 방식이 남는다. 무료 로컬 편집을 유지하며 ChatKit·provider는 [채팅 계획](character-chat-implementation-plan.md)의 교체 가능한 어댑터로 다룬다. 새 원격 공개·비용·계정 도입을 이번 전략으로 자동 실행하지 않는다.
