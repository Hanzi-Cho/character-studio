# My Character Library

2026-10-25 사용자 요청: 같은 캐릭터를 보관하고 표정·옷·장식을 바꿔 계속 사용하는 흐름을 구현한다. 새 클라우드·비용·분석 수집은 범위 밖이다. 기존 최소 화면과 대화상자 스타일을 확장하는 승인된 구현이며 새로운 프로젝트 단계 전이가 아니다.

## 사용 흐름

상단 **내 캐릭터 보관함** → 이름 입력 → **현재 모습 저장**. 최대 50개를 각각 보관한다. 목록의 **불러오기**로 현재 작업에 적용한 뒤 편집하고, 보관함을 다시 열어 **변경 저장**한다. **새 캐릭터로 저장**은 별도 버전을 만든다. 삭제 확인은 해당 보관본만 지우며 현재 작업은 유지한다.

현재 작업 자동 저장과 보관함은 별개다. 편집만 하면 보관본이 자동 갱신되지 않는다. 페이지 재시작 후 특정 보관본을 갱신하려면 먼저 목록에서 불러온다. 불러오기도 일반 patch/revision/undo 경로를 사용하므로 이전 작업으로 되돌릴 수 있다.

## 데이터·권한과 복구

- 포트 `CharacterLibrary`와 브라우저 어댑터를 분리한다. UI는 저장 기술을 알지 못한다. 서버·다른 저장소 구현으로 교체할 수 있다.
- `character-studio:library:v1`에 버전, 보관 ID, 이름, 수정 시각, revision과 `CharacterDocument`만 기록한다. 원본 이미지·렌더 메시·PNG·채팅·API 키는 포함하지 않는다.
- 웹과 로컬 실행 모두 사이트 origin별 localStorage를 사용한다. 같은 origin의 탭끼리 목록을 갱신하며 Web Locks로 쓰기를 직렬화한다. 수정/삭제는 보관본 revision을 재검사해 오래된 탭의 덮어쓰기를 거부한다.
- 이 브라우저를 사용하는 사람에게 보관함이 보인다. 계정별 격리·공유·기기 간 자동 동기화는 없다. 사이트 데이터 삭제, 시크릿 모드 종료 등에 대비해 각 보관본의 JSON을 다운로드한다. 채팅 + 버튼으로 JSON을 불러와 다시 저장할 수 있다.
- 손상·권한 거부·용량 부족은 오류로 안내하고 기존 데이터를 기본값으로 덮어쓰지 않는다. 50개 제한에서도 기존 캐릭터를 자동 삭제하지 않는다. v1/v2 캐릭터는 기존 스키마 마이그레이션을 재사용한다.
- JSON은 UTF-8의 압축하지 않은 공백 없는 설정 파일이다. UI의 용량은 개별 캐릭터 JSON의 바이트 수이며 localStorage의 실제 할당량·목록 메타데이터·이력·렌더러 코드는 제외한다. PNG로는 편집 상태를 복원할 수 없다.

## 요구와 검증

- LIB-01 저장·다중 보관·재열기: 독립 저장본과 페이지 새로고침 후 유지. 코드 `BrowserCharacterLibrary`, 화면 `CharacterLibraryDialog`.
- LIB-02 불러오기·계속 수정·별도 저장: 기존 `StudioGateway.patch` 및 undo/redo를 재사용. 다른 보관본은 변경하지 않는다.
- LIB-03 손상·저장 실패·충돌·한도: 기존 데이터 보존, stale update/delete 거부, 최대 50개 이후 생성 거부.
- LIB-04 내보내기·삭제: 다운로드는 복원 가능한 기존 CharacterDocument 계약. 삭제 확인/취소 UI; 삭제해도 현재 작업 보존.
- LIB-05 최소 저장·비밀 제외: strict 스키마, JSON 바이트 측정, API 키 등 미허용 필드 거부.

자동 검증: `tests/characterLibrary.test.ts`의 5개 시나리오, 기존 회귀 포함 총 44개 통과. 타입 검사와 로컬/정적 웹 빌드 통과. Windows PC 실제 브라우저에서 예문 입력→셔츠·날개·웃음→보관, 우사기 별도 저장, 새로고침 후 두 보관본 유지, 불러오기→되돌리기와 로컬 변경 저장을 확인했다. 보관함의 JSON 다운로드→+ 버튼으로 같은 파일 가져오기→치이카와·웃음·셔츠·날개 복원도 실제 화면에서 확인했다. 삭제 실행·quota·동시 쓰기·스키마 손상은 자동 테스트 근거다. 모바일 실기기·장기간 데이터 보존은 미검증이다.

용량 재현: `node --import tsx scripts/measure-character-storage.ts`. 측정 결과는 [storage-sizes.json](../evidence/character-library-v1/storage-sizes.json), 실제 화면은 같은 evidence 폴더에 기록한다. 수치는 임의 3D 모델 일반의 용량이 아니라 현재 절차적 캐릭터 예시다.

## AI와 예문

공개 웹: **내 AI 연결** → 본인 API 키 입력 → 전송·사용료 동의 → API 키 연결 → 사용 모델 선택 → 닫고 자유 채팅. 키는 탭 메모리에만 유지된다. 로컬 실행: 같은 창의 **Continue with ChatGPT** → 공식 계정·권한 동의 → 돌아와 모델 선택 → 자유 채팅. 서버 재시작 시 다시 연결한다. 로컬 기존 Codex CLI 경로도 유지한다.

AI 없이: 추천 예문 새로고침 → **바로 적용**, 또는 예문 원문을 채팅에 입력. 41개 저장된 EditPlan이 동일 검증·반영 경로를 사용한다. 참고 이미지를 첨부한 요청이나 예문을 벗어난 자유 요청은 실제 AI 연결이 필요하다. 예문 동작을 AI 추론 성공으로 집계하지 않는다.
