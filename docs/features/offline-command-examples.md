# Offline Command Examples

2026-10-25 사용자 요청: Codex 연결 없이 테스트할 예문을 30개 이상 저장하고, 하나씩 추천·새로고침·적용한다.

## 사용 흐름

[웹 데모](https://hanzi-cho.github.io/character-studio/), `pnpm demo` 또는 Windows의 `Start-Demo.cmd`로 시작한다. 추천 카드에는 문장 하나와 새로고침·적용 버튼만 표시한다. “AI 없이 체험”, 분류, 번호/전체 개수는 표시하지 않는다. 첫 추천부터 무작위다. **바로 적용**을 누르면 입력 없이 캐릭터에 반영한다. **추천 예문 새로고침**은 현재 문장을 제외한 40개 중 하나를 균등하게 무작위 선택한다. 이전에 본 문장이 나중에 다시 나올 수 있다. 추천 변경은 저장이나 모델 호출을 하지 않는다.

표정 버튼 위의 고정 상태 영역은 처음부터 “예문이나 표정을 골라 캐릭터를 바꿔보세요.”를 표시한다. 처리 중·예문 적용·표정 변경·복구·파일 작업·오류를 같은 영역에 표시하며 자동으로 사라지는 토스트를 띄우지 않는다. 상태 영역은 52px로 유지하고 긴 문장은 안에서 스크롤할 수 있다. 채팅 이력은 별도로 보존한다. 캐릭터 아래의 “작은 변화로, 나다운 캐릭터.” 문구는 제거했다.

같은 문장을 입력창에 붙여 넣어도 같은 결과다. 앞뒤·연속 공백과 유니코드 NFC만 정규화한다. 단어를 바꾸거나 부정문을 덧붙인 경우 예문으로 오인하지 않는다. Codex 모드의 나머지 입력은 실제 AI로 전달하며, 데모 모드는 기존 로컬 규칙으로 지원하는 속성만 처리하고 미지원 요청은 거부한다.

## 저장된 내용

정본은 [command-examples.json](../../src/domain/command-examples.json)이다. 각 항목은 `id`, `category`, `text`, `plan`을 가진다. `plan`은 실제 AI 출력과 같은 EditPlan 계약이다. 전체 색 8개, 볼 색 1개, 표정 6개, 비율 6개, 표준 장식 9개, 도형 장식 3개, 복합 편집 5개, 이름 1개, 장식 정리 1개, 초기화 1개로 총 41개다.

예문용 부위는 `sample-`로 시작하는 안정된 ID를 사용한다. 같은 예문을 다시 적용하면 해당 부위를 갱신하므로 중복으로 늘어나지 않는다. 다른 ID로 만든 사용자 부위는 유지한다. 크기 예문은 기본값 대비 절대 크기이며 반복 클릭으로 계속 커지지 않는다. 옷과 장식을 모두 지우기·전체 초기화는 문장에 명시된 범위대로 동작하며 undo로 복구할 수 있다.

## 연결 구조

추천 버튼 또는 입력 텍스트 → `/api/command` → `ExampleCommandInterpreter`의 정확한 예문 조회 → 저장된 EditPlan → `compilePlan`의 전체 검증 → CharacterService의 revision 검사 → 원자 저장 → SSE → 렌더러 갱신.

예문 어댑터가 Codex/로컬 해석기를 감싸며, 일치하는 예문은 후속 해석기에 전달하지 않는다. UI는 기존 `onSubmit` 계약만 사용하고 HTTP·모델·저장소를 직접 호출하지 않는다. 감사 정보에는 `provider: preset`, 예문 ID, 적용한 명령을 남긴다. 도형 수·부위 수·좌표 한도와 충돌·undo 정책은 AI 경로와 같다.

## 수용 기준과 범위

- 최소 30개 예문이 유효한 편집 명령을 가진다. 현재 41개를 실제 HTTP 경로로 적용·저장·undo 검증한다.
- 모델 해석기가 호출되면 실패하는 시험으로 예문 전체의 모델 호출 0회를 확인한다.
- 추천 새로고침은 상태를 변경하지 않으며 현재 문장과 다른 예문을 무작위 선택한다. 화면에는 번호를 표시하지 않는다.
- 오래된 revision, 잘못된 Origin, 예문에 부정문을 덧붙인 요청에서 원치 않는 변경이 없다.
- PC 화면에서 적용·추천 변경·직접 입력·undo/reset·재열기를 확인한다. 실제 모바일 기기 검증과 구분한다.
