기준: 2026-10-24, Linear P-HAN-43. 기존 v0의 2D 후보 4개 생성·선택 흐름은 제안 이력으로 보존한다. 이번 사용자는 3D 치이카와, 드래그 회전, 첨부한 최소 채팅 UI, PC 실행을 직접 지정하고 구현을 승인했다. 이 구체적 실행 범위를 현재 MVP 기준으로 삼고 과거의 2D 선택 질문을 반복하지 않는다.

## 지금 확정된 요구와 구현

- R01: 일반 비개발자 대상, PC 먼저 → 로컬 웹 앱과 재실행 파일. 최종 일반 사용자 배포 설치/연결 UX는 후속.
- R02: 3D 치이카와와 다방향 회전 → 절차적 mesh 모델, 마우스 드래그·휠·키보드, 정면 복귀. 이미지 평면 회전이 아니다.
- R03: 하단 최소 채팅에서 수정 → 실제 색상·귀/눈 크기·몸 비율·6개 표정·리본/별·이름을 검증된 patch로 적용. 6종 시안 선택은 표정만 변경한다. 로컬 명령 문법이며 임의 AI 대화/3D 생성이 아니다.
- R04: 저장/복구 → 로컬 파일, 50개 undo/redo, revision 충돌, JSON 내보내기/가져오기, PNG 저장.
- R05: 모바일 확장 → 반응형 배치, touch-action과 OrbitControls 경로 구현. 390×844 화면 검증. 실제 휴대폰 touch/성능과 앱 패키징 미검증.
- R06: AI/MCP → 실제 stdio 서버의 3개 도구와 표준 클라이언트 통합 검증. Gemini·Claude·GPT 앱 설치/연결/임베드 미검증.
- R07: Human Atlas 연구/재사용 → 고정 커밋 소스 연구, 원본 결합/성능 비용 분석, 어댑터와 persistent renderer 적용, 반복 메시 배치 실험. 원본 코드/해부 데이터는 복사하지 않았다.

## 이번에 해결된 결정

React·TypeScript + Three.js를 선택했다. 현재 모델은 절차적 geometry, 데이터는 CharacterDocument v1, UI/MCP는 동일한 편집 서비스를 쓴다. PC 로컬 데이터만 저장하고 외부 모델/API 비용은 사용하지 않는다. 사용자 첨부 채팅 UI를 직접 실행한 좁은 UI 승인으로 재사용하며, 이를 향후 모바일/클라우드/공개 출시 전체 UI 승인으로 확장하지 않는다.

## 사용자와 다음에 정할 것

1. **첫 실제 AI 호스트**: 현재 사용 중인 Gemini·Claude·GPT 중 어느 연결부터 검증할지. 호스트별 MCP/임베드·로컬/원격 지원 확인 후 무료로 가능한 경로를 제시한다.
2. **‘소통’ 범위**: 외형 편집만 우선인지, 캐릭터 성격·기억·음성·애니메이션까지 포함할지. 현재는 외형 편집만 동작한다.
3. **자유 수정의 깊이**: 현재 수치/색상 편집 확장, 모델 템플릿 추가, 혹은 텍스트로 새로운 3D 형상 생성 중 우선순위. 모델 생성 공급자/비용/시간은 미결정이다.
4. **모바일 범위**: Android 우선/양 OS, PC와 동기화 여부, 오프라인 요구. 이후 PWA/Capacitor/원격 서버 선택에 영향을 준다.
5. **대회 공개 시연 자산과 배포**: 현재 치이카와 스터디를 사용자가 확인한 뒤 공개용 독자 캐릭터/표현, 서비스명, 배포 위치를 결정한다. 공개 배포·외부 공유·제출은 하지 않았다.

위 질문은 다음 확장을 위한 결정이다. 현재 PC MVP 실행을 다시 승인받기 위한 질문이 아니다. 사용자의 이번 답변으로 대상·입력·출력·첫 플랫폼은 이미 정해졌다.

## 현재 단계와 차단 구분

MVP 구현/검증 단계에 해당한다. 로컬 데모 핵심 흐름을 확인했지만 사용자 실제 사용감 승인은 아직 없다. 제품화 전이는 하지 않는다. 일반 사용자용 MCP 연결, 실제 호스트·실기기, 설치/업데이트, 장기 저장/복구, 원격 소유권/동의가 핵심 잔여다.

현재 로컬 데모의 차단: 없음(아래 검증 보고서 범위). 후속 제품화 차단: 실제 AI 호스트/모바일 미검증, 범용 자유 형상 수정 미구현, 앱 배포·연결 UX 미완성. 모든 것을 사용자 만족이나 출시 완료로 취급하지 않는다.
